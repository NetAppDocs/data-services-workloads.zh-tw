[[workload-factory-administration-enhancements]]
=== Workload Factory 管理增強功能



==== 檢查並重新整理自訂儀表板資料

現在您可以查看自訂儀表板計量的最後更新時間，並手動重新整理它們。將滑鼠停留在 *重新整理資料* 上即可檢視最後更新的日期和時間。

選擇 *重新整理資料* 來開始新的掃描。橫幅會確認掃描已開始，且按鈕在掃描完成前將處於停用狀態。

當有新資料可用時，請在通知橫幅中選取 *立即載入* 以更新儀表板。

*重新整理資料* 和 *立即載入* 都會在 Tracker 中建立資料收集事件。

link:https://docs.netapp.com/us-en/data-services-workloads/admin/manage-custom-dashboards-fsx.html#refresh-dashboard-data["了解如何重新整理自訂儀表板資料"]



==== 為自訂儀表板指定區域

如果您的要求中未包含某些區域，自訂儀表板現在會要求您選擇一個或多個區域。儀表板資料僅限於您選擇的區域。

link:https://docs.netapp.com/us-en/data-services-workloads/admin/create-custom-dashboard-fsx.html["了解如何建立自訂儀表板"]



==== 用於建立 FSx for ONTAP 連結的 IAM 原則

用於建立連結的 CloudFormation 範本和 Terraform 程式碼現在使用 IAM 原則，而不是即時 Lambda 權限。

link:https://docs.netapp.com/us-en/data-services-workloads/fsx-storage/create-link.html["學習如何建立連結"]



==== AI 代理程式行為的稽核與追蹤

現在您可以使用 Tracker 審查 AI 代理程式設定的變更，並且在讀寫模式下，還可以查看每個核准要求，包括代理程式的問題和使用者的答案。

透過 Workload Factory API 進行的資源變更由執行該操作的 Workload Factory 服務記錄。

link:https://docs.netapp.com/us-en/data-services-workloads/admin/learn-agent.html["了解代理程式操作的稽核和追蹤"]



[[amazon-fsx-for-netapp-ontap-enhancements]]
=== Amazon FSx for NetApp ONTAP 增強功能



==== 啟動器群組圖表增強

「管理用戶端存取」頁面上用於顯示區塊裝置啟動器群組的圖表現在包含更多主機詳細資訊。將滑鼠懸停在圖表中的主機上時，將顯示主機詳細資訊，包括主機名稱、執行個體 ID、工作負載類型、區域和 iSCSI 限定名稱（IQN）。



==== 針對架構完善的問題進行電子郵件增強

新的電子郵件設計針對 Workload Factory 偵測到的組態問題，提供更多詳細資料與背景資訊。電子郵件包含已分析的資源數量、有多少資源發生警告或關鍵問題，以及這些問題是什麼。電子郵件也會連結至 FSx for ONTAP 完善架構儀表板，讓您可以立即解決問題。



==== 精心設計的儀表板增強功能



===== 支援選定的組態檢查

您可以手動對選定的組態執行分析，以便只分析您感興趣的組態，從而減少等待時間。



===== 架構良好的分析中的新建議

Workload Factory 現在在針對 FSx for ONTAP 檔案系統的完善架構分析中加入了以下配置：

對於儲存設備工作負載：

* *將主機連線至容錯移轉節點*：檢查主機是否已連線至主動被動式 FSx for ONTAP 檔案系統中的容錯移轉節點，以確保可靠性。
* *將主機連接至首選節點*：檢查主機是否使用首選節點連接至其區塊裝置，以提升效能與效率。
* *ARP/AI 多裝置偵測漏洞*：當一個 Volume 僅連接一個區塊裝置時，ARP/AI 可提供全面的保護。如果一個 Volume 連接了多個區塊裝置，Workload Factory 會將這些區塊裝置移至新的 Volume，以確保每個 Volume 僅連接一個區塊裝置。
* *複製清理*：檢查是否有超過 30 天的 Volume 複製可以刪除，以最佳化儲存設備使用並降低成本。
* *將 igroup 作業系統與主機配對*：檢查啟動器群組（igroup）的作業系統是否與主機的作業系統相符，以防止 I/O 或效能問題。


對於 Kubernetes 工作負載：

* *QoS 組態*：檢查 Kubernetes 持久性 Volume 是否受到 ONTAP QoS 原則的保護，以確保效能與效率。
* *專用 Kubernetes 儲存設備 VM*：檢查檔案系統是否使用專用儲存設備 VM 來處理 Kubernetes 工作負載，以提高隔離並簡化儲存管理。
* *專用 Kubernetes 匯出原則*：檢查每個 Kubernetes 持久性 Volume 是否具有專用的匯出原則，該原則僅允許從叢集的工作節點進行存取。
* *Kubernetes iSCSI 後端的雙向 CHAP*：檢查 Trident iSCSI 後端是否已啟用相互 CHAP 驗證以確保安全性。
* *在應用程式儲存設備 VM 上停用 `showmount`*：檢查在應用程式儲存設備 VM 上是否已停用 `showmount`，以防止用戶端列出其無法存取的匯出。


對於資料庫工作負載：

* *SAP HANA 快照原則*：檢查 SAP HANA Volume 的快照原則是否設定為「無」，以降低儲存設備成本並提高作用中資料庫資料的效能。
* *MySQL 快照原則*：檢查 MySQL Volume 的快照原則是否設定為「無」，以降低儲存設備成本並提高作用中資料庫資料的效能。
* *PostgreSQL 快照原則*：檢查 PostgreSQL Volume 的快照原則是否設定為「None」，以降低儲存設備成本並提高作用中資料庫資料的效能。




===== 組態的目前和建議值

您可以在設計完善的儀表板中檢視某些未最佳化組態的目前值和建議值。這可讓您在修復之前了解建議值為何。

* 冷資料分層
* Snapshot 原則
* SSD 容量餘裕




==== 成本改進



===== 成本預測與洞察

現在，您可以使用成本預測功能來預測 FSx for ONTAP 檔案系統的成本。這有助於您有效地規劃預算並最佳化資源。您也可以檢視有關成本和使用模式的深入分析，以找出成本最佳化的機會。



===== AWS 成本和使用情況報告（CUR）

Workload Factory 現在使用 AWS 成本和使用情況報告（CUR）而非 AWS Cost Explorer 來提供詳細的帳單記錄，並將這些記錄傳送到客戶擁有的 S3 儲存桶。CUR 提供更佳的成本精細度，並為進階 FinOps、退款和成本分配使用案例奠定基礎。



==== 儲存虛擬機器移轉改進

Workload Factory 在使用者介面中提供了增強的儲存設備虛擬機器移轉指導。這包括逐步說明和在將移轉提交到生產環境之前進行的測試執行。

link:fsx-storage/create-replication.html["了解更多關於儲存設備 VM 移轉"]



==== 複寫延遲電子郵件通知改善

當發生大量相關的複寫延遲事件時，Workload Factory 會自動將它們合併到單一電子郵件通知中，這樣您就不會被通知淹沒。



==== 自動容量管理增強

現在您可以啟用自動容量管理通知功能，以便在要求 Workload Factory 自動管理容量之前先體驗該功能。當您的檔案系統容量不足時，您將收到通知。



==== 包含在架構良好儀表板中的資料庫組態

精心設計的儀表板現在包含資料庫配置建議，方便您根據最佳實踐評估和優化您的設定。儀表板中包含的首批配置如下：

* 冷資料分層
* 儲存效率
* Snapshot 原則
* SSD 容量餘裕
* 區塊設備空間管理
* OS 類型
* 將區塊設備作業系統類型與主機匹配
* 非作用中區塊裝置（LUN）
* 資料檔（.mdf）放置
* 日誌檔（.ldf）放置
* 多路徑 I/O 狀態
* 多路徑 I/O 逾時
* 叢集仲裁
* 運算規模調整


在 Workload Factory 控制台中選擇主選單，然後選擇 *架構完善* 以尋找架構完善的儀表板。

image:well-architected-menu-option.png["Workload Factory 控制台中設計良好的選單選項"]



==== 處理量決策點

現在您可以查看用戶端處理量建議和自動化決策點。將滑鼠懸停在決策點上即可檢視詳細資訊，例如目前和建議的 SKU 或時間範圍內的超標計量（%）。



[[workload-factory-for-vmware-enhancements]]
=== Workload Factory for VMware 增強功能

這些增強功能涵蓋了 VMware 遷移的 EVS TCO 計算器。



==== EVS TCO 計算器支援 i7i.metal-24xl 和 i7i.metal-48xl 執行個體

EVS TCO 計算器現在支援將 AWS i7i.metal-24xl 和 i7i.metal-48xl EC2 執行個體作為叢集主機。與 i4i.metal 配置相比，i7i.metal-24xl 執行個體可將 EVS 的運算初始成本降低約 33%，vSAN 儲存設備初始成本降低約 25%。

此計算器會比較所有執行個體類型，並自動選擇成本最低的方案。新增的比較部分並排顯示 EVS 主機配置，方便您根據自身需求選擇最佳設定。

link:https://docs.netapp.com/us-en/data-services-workloads/fsx-vmware/calculate-evs-savings.html["計算 EVS 的預計節省量"]



[[workload-factory-for-eda-enhancements]]
=== Workload Factory for EDA 增強功能

這些增強功能涵蓋了延遲分析中的 Volume 細節、檔案系統壓力檢查、處理量決策點以及再次執行延遲分析。



==== 在延遲分析期間檢視 Volume 詳情

在分析延遲事件時，您可以在 Workload Factory 中檢視更多 Volume 詳細資訊，以便了解 Volume 的組態方式。「詳細延遲分析」頁面會顯示 *Volume 類型*（RW 或 DP）和 *Volume 樣式*（FlexVol 或 FlexGroup）。

link:https://docs.netapp.com/us-en/data-services-workloads/fsx-eda/task-analyze-latency-trends.html["瞭解如何分析延遲趨勢"]



==== 檢查延遲事件的檔案系統壓力

在 Workload Factory 中，您可以檢查延遲事件發生時檔案系統壓力是否影響了效能，以便決定是否需要調查檔案系統。對於發出延遲警報的 Volume，您可以檢視事件發生前 40 分鐘的 CloudWatch 資料，並開啟檔案系統進行進一步調查。

link:https://docs.netapp.com/us-en/data-services-workloads/fsx-eda/learn-latency-monitoring.html#file-system-pressure["了解檔案系統壓力檢查"]



==== 審查 EDA 的處理量決策點

您可以在 EDA 概覽儀表板審查用戶端處理量決策點，以便了解 Workload Factory 何時建議或套用了處理量變更。將滑鼠懸停在決策點上即可檢視詳細資訊，例如目前和建議的 SKU 或該時間視窗內超出限制的計量。

link:https://docs.netapp.com/us-en/data-services-workloads/fsx-eda/task-use-overview-dashboard.html#analyze-capacity-and-throughput-trends-and-decision-points["了解如何審查處理量決策點"]



==== 再次執行延遲分析

您可以在 Workload Factory 中對 Volume 再次執行延遲分析，以便在調查或進行變更後重新整理結果。選取 *再次執行分析* 以開始新的分析並更新結果。

link:https://docs.netapp.com/us-en/data-services-workloads/fsx-eda/task-analyze-latency-issues.html["了解如何分析延遲問題"]

=== Google Cloud NetApp Volumes 功能增強



==== 檢視 Google Cloud NetApp Volumes 儲存資源池

您現在可以在 NetApp Workload Factory 中檢視您的 Google Cloud NetApp Volumes 儲存資源池。依專案、憑證和地區進行篩選，並選取儲存資源池的名稱以檢視其完整詳細資料，包括可用區、複本可用區、處理量、執行摘要和標籤。



[[oci-netapp-storage-service-enhancements]]
=== OCI NetApp 儲存服務增強功能



==== 針對 OCI NSS 系統的架構良好的分析

NetApp Workload Factory 包含針對 OCI NSS 系統精心設計的評估。此評估提供洞察分析、建議和解決方案，幫助您實現卓越營運績效。

OCI Well-Architected Framework 的下列支柱可提供組態評估：

* 可靠性：檔案物件容量、Snapshot 快照技術原則和 SSD 容量餘裕
* 卓越營運績效：主機可見的容量報告和 Volume 容量餘裕
* 成本最佳化：冷資料分層、快照清理與儲存設備效率


了解更多關於 link:https://docs.netapp.com/us-en/data-services-workloads/oci/add-credentials-oci.html["針對 OCI NSS 系統的架構完善分析"] 與 link:https://docs.netapp.com/us-en/data-services-workloads/oci/improve-configurations.html["實作架構良好的組態"] 的資訊。
