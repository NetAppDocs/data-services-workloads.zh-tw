= 設定 NetApp Workload Factory 通知
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
您可以設定 NetApp Workload Factory 通知服務，使其將通知以警報形式傳送至 NetApp Console、帳戶關聯的任何電子郵件地址或 Amazon SNS 主題。如果您已部署 Console 代理或鏈接，則以警報形式傳送的通知將顯示在 NetApp Console 中。當 Workload Factory 將通知發佈到 Amazon SNS 主題時，該主題的訂閱者（例如使用者或其他應用程式）將透過為該主題配置的端點（例如電子郵件或簡訊）接收通知。



[[configure-workload-factory-notifications]]
== 設定 Workload Factory 通知

您可以使用 NetApp Console 設定 Workload Factory 通知。

以下是可用的通知選項：* *通知*：設定 Workload Factory 以傳送顯示在 NetApp Console 鈴鐺圖示下的通知。* *電子郵件*：在 NetApp Console 中啟用電子郵件通知，即可接收發送至與該帳戶關聯的任何電子郵件地址的通知，而無需組態 Amazon SNS。* *Amazon SNS*：設定 Workload Factory 以將通知傳送至 Amazon SNS 主題。

.開始之前
以下先決條件僅適用於設定 Amazon SNS 通知時：

* 您需要設定 Amazon SNS 並使用 Amazon SNS 主控台或 AWS CLI 建立 Amazon SNS 主題。
* 請注意，Workload Factory 支援 *標準* 主題類型。此類主題無法保證通知會按照接收順序發送給訂閱者，因此如果您有關鍵或緊急通知，請將此納入考量。


.步驟
. 登入 link:https://console.netapp.com["NetApp Console"^]。
. 從 NetApp Console 選單中，選擇 *工作負載*、*管理*，然後選擇 *通知設定*。
. 在「通知」設定頁面上，啟用下列一或多種通知類型：
+
.. *NetApp Console 通知*：選擇*啟用 NetApp Console 通知*以設定 Workload Factory 在 NetApp Console 中傳送通知。
.. *電子郵件通知*：選取 *啟用電子郵件通知*，將 Workload Factory 設定為傳送通知至與該帳戶相關聯的任何電子郵件地址。
.. *Amazon SNS 通知*：選取*啟用 SNS 通知*，然後依照指示從 Amazon SNS 主控台設定 Amazon SNS。
+
建立主題後，複製主題 ARN 並將其輸入到 *通知設定* 頁面上的 *SNS 主題 ARN* 欄位中。



. 傳送測試通知以驗證組態後，選取 *套用*。




[[subscribe-to-the-amazon-sns-topic]]
== 訂閱 Amazon SNS 主題

設定 NetApp Console 向某個主題發送通知後，請依照 Amazon SNS 文件中的 https://docs.aws.amazon.com/sns/latest/dg/sns-create-subscribe-endpoint-to-topic.html["指示"]訂閱該主題，以便接收來自 Workload Factory 的通知。



[[filter-notifications]]
== 篩選通知

您可以透過對通知套用篩選器，減少不必要的通知流量，並針對特定使用者推播特定類型的通知。您可以使用 Amazon SNS 策略來管理 SNS 通知，也可以在 NetApp Console 中使用通知設定來實現這一點。



[[filter-amazon-sns-notifications]]
=== 篩選 Amazon SNS 通知

訂閱 Amazon SNS 主題後，您會在預設情況下收到發佈到該主題的所有通知。如果您只想接收來自該主題的特定通知，可以使用篩選原則來控制接收哪些通知。篩選原則會使 Amazon SNS 僅向訂閱者交付符合篩選原則的通知。

您可以依照以下條件篩選 Amazon SNS 通知：

[cols="3*"]
|===
| 說明 | 篩選原則欄位名稱 | 可能的值 


| 資源類型 | `resourceType`  a| 
* `DB`
* `Microsoft SQL Server host`
* `PostgreSQL Server host`




| 工作負載 | `workload` | `WLMDB` 


| 優先順序 | `priority`  a| 
* `Success`
* `Info`
* `Recommendation`
* `Warning`
* `Error`
* `Critical`




| 通知類型 | `notificationType`  a| 
* `Deployment`
* `Well-architected`


|===
.步驟
. 在 Amazon SNS 主控台中，編輯 SNS 主題的訂閱詳細資訊。
. 在 *訂閱篩選原則* 區域中，選擇按 *訊息屬性* 進行篩選。
. 啟用 *訂閱篩選原則* 選項。
. 在 *JSON 編輯器* 方塊中輸入 JSON 篩選原則。
+
例如，以下 JSON 篩選原則接受來自 Microsoft SQL Server 資源、與 WLMDB 工作負載相關的通知，其優先順序為「成功」或「錯誤」，並提供有關架構良好狀態的詳細資訊：

+
[source, json]
----
{
  "accountId": [
    "account-a"
  ],
  "resourceType": [
    "Microsoft SQL Server host"
  ],
  "workload": [
    "WLMDB"
  ],
  "priority": [
    "Success",
    "Error"
  ],
  "notificationType": [
    "Well-architected"
  ]
}
----
. 選擇 *Save changes*。


有關其他過濾原則的範例，請參閱 https://docs.aws.amazon.com/sns/latest/dg/example-filter-policies.html["Amazon SNS 範例篩選原則"^]。

如需建立篩選原則的進一步資訊，請參閱 https://docs.aws.amazon.com/sns/latest/dg/sns-message-filtering.html["Amazon SNS 文件"^]。



[[filter-notifications-in-netapp-console]]
=== 在 NetApp Console 中篩選通知

您可以使用 NetApp Console 通知設定，依嚴重性層級（例如 Critical、Info 或 Warning）篩選您在 Console 中收到的通知。

如需有關在主控台中篩選通知的詳細資訊，請參閱 https://docs.netapp.com/us-en/console-setup-admin/task-monitor-cm-operations.html#filter-notifications["NetApp Console 文件"^]。
