= 管理 NetApp Workload Factory 連結
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
管理與您的 Workload Factory 帳戶關聯的連結。您可以檢視與 FSx for ONTAP 檔案系統或 OCI NetApp 儲存服務（OCI NSS）系統關聯的連結，提供用於連結驗證的密碼，以及從 NetApp Console 移除連結。

link:../setup/links-overview.html["了解更多關於連結的資訊。"]

當有更新的連結版本可用時，使用者介面會自動通知您並提供升級說明。



[[view-the-links-associated-with-your-account]]
== 檢視與您的帳戶關聯的連結

您可以檢視目前與您的帳戶關聯的連結。

.步驟
. 選擇選單 image:workloads-menu-icon.png["漢堡選單圖示用於導覽至 Workloads ，這是 Workload Factory 的選單項目"]，*管理* > *連結*。
+
現有連結顯示在「連結」頁面上。

. 若要檢視與連結關聯的儲存系統，請在「關聯資源」部分選擇 *檢視* 按鈕。
. 如果您需要連結的 Amazon Resource Name（ARN），您可以選擇 ARN 欄位旁邊的 _copy_ 圖示。




[[edit-a-link]]
== 編輯連結

您無法從 NetApp Console 編輯連結。如果您需要變更連結，則需要建立新連結，然後將該連結與您的儲存系統建立關聯。


NOTE: 您可以使用雲端供應商的主控台編輯 AWS Lambda 或 Oracle Cloud Functions 網路組態（例如 VPC、子網路和安全性群組），變更將反映在連結或 Functions 管理 UI 中；但是，這些變更可能會導致 AWS Lambda 或 Oracle Cloud Functions 與 ONTAP 之間的連線問題，因此不建議這樣做。



[[authenticate-a-link]]
== 驗證連結

透過提供 Workload Factory 認證資料的管理員使用者密碼，或來自 AWS Secrets Manager 或 Oracle Vault 的機密來驗證連結。

* 對於 AWS Secrets Manager，請提供機密名稱或 AWS Secrets Manager 機密 ARN，以將連結連接到 FSx for ONTAP 檔案系統。
+

NOTE: 使用 Console 代理程式時不支援 AWS Secrets Manager。

* 對於 Oracle Vault，請提供保存庫密鑰 OCID，以將連結連接至 OCI NetAApp Storage Service 系統。



NOTE: 每個連結僅支援一種身分驗證方法。例如，如果您選擇使用 AWS Secrets Manager 進行連結驗證，則之後無法變更身分驗證方法。

[role="tabbed-block"]
====
.Amazon FSx for NetApp ONTAP
--
.步驟
. 登入 link:https://console.netapp.com["NetApp Console"^]。
. 選擇選單 image:workloads-menu-icon.png["漢堡選單圖示用於導覽至 Workloads ，這是 Workload Factory 的選單項目"]，*工作負載* > *儲存設備* > *FSx for ONTAP*。
. 從 *FSx for ONTAP* 中，選取要關聯連結之檔案系統的動作選單，然後選取 *管理*。
. 在檔案系統總覽中，選擇 *驗證連結*。
. 在「驗證」連結頁面中，選擇一種驗證模式：
+
** *Workload Factory*：請輸入兩次密碼。
** *AWS Secrets Manager*：輸入機密 ARN。


. 選擇 *Apply*。


--
.OCI NetApp 儲存服務
--
.步驟
. 登入 link:https://console.netapp.com["NetApp Console"^]。
. 選擇選單 image:workloads-menu-icon.png["漢堡選單圖示用於導覽至 Workloads ，這是 Workload Factory 的選單項目"]，*工作負載* > *儲存設備* > *OCI NetApp Storage Service*。
. 從 *OCI NetApp 儲存服務* 中，選取要關聯連結的儲存資源池動作選單，然後選取 *管理*。
. 在儲存資源池總覽中，選擇 *驗證連結*。
. 在「驗證」連結頁面中，選擇一種驗證模式：
+
** *Workload Factory*：請輸入兩次密碼。
** *OCI Vault*：輸入秘密 OCID。


. 選擇 *Apply*。


--
====
.結果
連結已驗證，您可以執行進階 ONTAP 作業



[[update-the-password-for-link-authentication]]
== 更新連結驗證密碼

當管理密碼無效時，請更新密碼以將連結連接至您的儲存系統。

[role="tabbed-block"]
====
.Amazon FSx for NetApp ONTAP
--
.步驟
. 登入 link:https://console.netapp.com["NetApp Console"^]。
. 選擇選單 image:workloads-menu-icon.png["漢堡選單圖示用於導覽至 Workloads ，這是 Workload Factory 的選單項目"]，*工作負載* > *儲存設備* > *FSx for ONTAP*。
. 從 *FSx for ONTAP* 中，選取要關聯連結之檔案系統的動作選單，然後選取 *管理*。
. 在檔案系統總覽中，選擇 *更新密碼*。
. 在驗證連結頁面中，輸入新密碼兩次。
. 選擇 *Apply*。


--
.OCI NetApp 儲存服務
--
.步驟
. 登入 link:https://console.netapp.com["NetApp Console"^]。
. 選擇選單 image:workloads-menu-icon.png["漢堡選單圖示用於導覽至 Workloads ，這是 Workload Factory 的選單項目"]，*工作負載* > *儲存設備* > *OCI NetApp Storage Service*。
. 從 *OCI NetApp 儲存服務* 中，選取要關聯連結的儲存資源池動作選單，然後選取 *管理*。
. 在儲存資源池總覽中，選擇 *更新密碼*。
. 在驗證連結頁面中，輸入新密碼兩次。
. 選擇 *Apply*。


--
====
.結果
密碼已更新，連結現已連接到儲存系統。



[[remove-a-link]]
== 移除連結

您可以移除環境中不再使用的連結。連結移除後，任何使用該連結的儲存系統或其他資源都將無法使用某些功能。

請注意，該連結僅從 Workload Factory 中刪除，不會從您的 AWS 或 Oracle 環境中刪除。

* 對於 FSx for ONTAP，在 Workload Factory 中移除連結後，您必須從 AWS 帳戶中刪除 Lambda 函數。
* 對於 OCI NetApp 儲存設備服務，在 Workload Factory 中移除連結後，您必須從 OCI 帳戶中刪除函數執行個體。


[role="tabbed-block"]
====
.Amazon FSx for NetApp ONTAP
--
.步驟
. 登入 link:https://console.netapp.com["NetApp Console"^]。
. 選擇選單 image:workloads-menu-icon.png["漢堡選單圖示用於導覽至 Workloads ，這是 Workload Factory 的選單項目"]，*管理* > *連結*。
+
現有連結顯示在「連結」頁面上。

. 在「連結」頁面中，選擇要移除之連結的操作選單，然後選擇 *移除*。
. 如果您確定，請再次選擇 *移除*。


請參閱 AWS 文件以link:https://docs.aws.amazon.com/lambda/latest/dg/gettingstarted-awscli.html#with-userapp-walkthrough-custom-events-delete-function["刪除 Lambda 函數"]。

--

+
現有連結顯示在「連結」頁面上。

. 在「連結」頁面中，選擇要移除之連結的操作選單，然後選擇 *移除*。
. 如果您確定，請再次選擇 *移除*。
