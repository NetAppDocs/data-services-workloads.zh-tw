= 了解 NetApp Workload Factory for VMware
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
NetApp Workload Factory for VMware 提供工具，可將您的資料從本機系統移轉到 Amazon Elastic VMware Service （EVS）、VMware Cloud on AWS （VMC）、Amazon EC2 或 Google Cloud VMware Engine。



[[what-is-netapp-workload-factory-for-vmware]]
== 什麼是適用於 VMware 的 NetApp Workload Factory？

NetApp Workload Factory for VMware 提供規劃中心和遷移顧問，協助您分析本地 vSphere 環境中的目前虛擬機器配置。遷移顧問隨後會產生一個計劃，將推薦的虛擬機器佈局部署到 Amazon EVS、Amazon EC2、VMware Cloud on AWS vSphere 叢集或 Google Cloud VMware Engine，並使用自訂的雲端原生儲存作為外部資料儲存。對於 AWS 環境，這包括 Amazon FSx for NetApp ONTAP 檔案系統。對於 Google Cloud 環境，這包括 Google Cloud NetApp Volumes。規劃中心作為 Workload Factory for VMware 的控制面板，可讓您管理已儲存的虛擬機器清單資料集和已儲存的遷移計劃，並配置任何已儲存的遷移計劃。

Amazon FSx for NetApp ONTAP 是一個建構於 NetApp 的 ONTAP 檔案系統上的外部 NFS 資料存放區，可以掛載到 Amazon EVS 或 Amazon EC2 執行個體，或 VMware Cloud on AWS vSphere 叢集。同樣地，Google Cloud NetApp Volumes 為 Google Cloud VMware Engine 環境提供外部 NFS 資料存放區。無需新增更多主機來增加可用儲存空間，只需使用這些雲端原生儲存磁碟區作為外部資料存放區，以補充 vSAN 資料存放區。這為您提供一個靈活、高效能且虛擬化的儲存基礎架構，能夠獨立於運算資源進行擴展。

如需有關 Workload Factory 的詳細資訊，請參閱 link:../setup/learn-about-workload-factory.html["Workload Factory 總覽"^]。



[[how-the-vmware-migration-advisors-work]]
== VMware 移轉顧問的工作原理

遷移顧問可以幫助您將運行在任何 VMware 支援的資料儲存上的本機虛擬機（VM）及其資料遷移到 Amazon EVS、Amazon EC2、VMware Cloud 或 Google Cloud VMware Engine 資料存儲，其中包括在 FSx for ONTAP 檔案系統或 Google Cloud NetApp Volumes 上的補充 NFS 資料儲存。

請注意，您可以將最多四（4）個 FSx for ONTAP Volume 附加到 VMware Cloud on AWS 上的單一 vSphere 叢集。



[[what-you-can-do-with-the-migration-advisors]]
== 您可以使用移轉顧問執行的作業

移轉顧問提供以下功能：

* 分析目前的內部部署 VM 組態
* 決定要將哪些虛擬機器移轉到 Amazon EC2、Amazon EVS、VMware Cloud on AWS 或 Google Cloud VMware Engine
* 確定用作 VM 外部資料存放區所需的雲端原生儲存磁碟區空間
* 審查產生的報告，了解部署步驟
* 執行實際部署（適用於 Amazon EC2、Amazon EBS 和 VMware Cloud on AWS）


遷移顧問支援針對單一 Amazon EVS、Amazon EC2 或 VMware Cloud on AWS 叢集，連接至 Amazon FSx for NetApp ONTAP 檔案系統，或連接至 Google Cloud VMware Engine 叢集與 Google Cloud NetApp Volumes 的組態規劃。



[[benefits-of-using-the-migration-advisors]]
== 使用移轉顧問的好處

將您目前基礎架構的部分內容移轉到 Amazon EC2、Amazon EBS、VMware Cloud on AWS 或 Google Cloud VMware Engine，並使用雲端原生儲存作為外部 NFS 資料存放區，可帶來以下好處：

* 透過主機和儲存設備解耦以及進階資料效率實現成本優化
* 能夠根據需要擴充儲存容量，而無需購買額外的主機執行個體
* NetApp ONTAP 在雲端的資料管理員功能，例如節省空間的快照、複製、壓縮、重複資料刪除、資料精簡與複寫
* 減少硬體更新管理工作
* 能夠更改資料處理量、IOPS 和檔案系統大小，以及增加或減少磁碟區的大小
* 支援多可用區（AZ）部署的高可用度
* 透過使用 VPC 對等關係而無需 Transit Gateway 的單一可用區配置來降低成本和延遲




[[tools-to-use-netapp-workload-factory]]
== 使用 NetApp Workload Factory 的工具

您可以將 NetApp Workload Factory 與下列工具搭配使用：

* *Workload Factory 控制台*：Workload Factory 控制台提供應用程式和專案的視覺化、整體檢視。
* *NetApp Console*：NetApp Console 提供混合介面體驗，讓您可以將 Workload Factory 與其他 NetApp 資料服務搭配使用。
* *Ask me*：使用 Ask me AI 助理來提問，無需離開 Workload Factory 主控台即可了解更多關於 Workload Factory 的資訊。您可以從 Workload Factory 說明選單存取 Ask me。
* *CloudShell CLI*：Workload Factory 包含一個 CloudShell CLI，可透過單一、以瀏覽器為基礎的 CLI，跨帳戶管理及操作 AWS 與 NetApp 環境。從 Workload Factory 主控台的頂部列存取 CloudShell。
* *REST API*：使用 Workload Factory REST API 部署和管理您的 FSx for ONTAP 檔案系統和其他 AWS 資源。
* *CloudFormation*：使用 AWS CloudFormation 程式碼執行您在 Workload Factory 主控台中定義的行動，以從您 AWS 帳戶中的 CloudFormation 堆疊，建模、資源配置及管理 AWS 與第三方資源。
* *NetApp Terraform 供應商*：使用 Terraform 建置和管理在 Workload Factory 主控台中產生的基礎架構工作流程。




[[well-architected-analysis-for-evs-environments]]
== 針對 EVS 環境的架構完善分析

「架構完善」標籤可對您的 Amazon Elastic VMware Service (EVS) 環境進行每日自動分析，以確保其符合 AWS 和 NetApp 最佳實務。此標籤可識別配置問題，並提供詳細的修復指南，幫助您維持最佳的運作、安全性和成本效益。

自動掃描使用 AWS API 執行，無需 vSphere 憑證。掃描結果按配置區域進行分類，每項結果都包含狀態、嚴重程度、受影響資源的詳細資訊以及逐步修復程序。

link:view-evs-well-architected.html["在 Workload Factory 中實施架構良好的 EVS 配置"]。
