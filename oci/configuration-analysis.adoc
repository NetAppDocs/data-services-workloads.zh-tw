= OCI NSS 系統的組態分析
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
NetApp Workload Factory 會定期分析 OCI NSS 系統組態，以判斷是否有任何組態問題。發現問題時，Workload Factory 會向您顯示問題所在，並說明需要變更的內容，讓您的儲存環境達到最佳效能、成本效率，並法規遵循最佳實務做法。

主要功能包括：

* 每日配置分析
* 自動最佳實務驗證
* 主動可觀測性
* 洞察化為行動
* OCI 架構完善框架顧問




[[how-it-works]]
== 運作方式

Workload Factory 每天都會對支援的雲端儲存部署上的工作負載進行分析。分析結果提供架構完善的狀態資訊、洞察與建議。

每日分析完成後，部署的「架構完善」儀表板會將組態顯示為「最佳化的」或「未最佳化的」。您可以在這裡找到按類別組織的組態問題以及相應的建議。Workload Factory 會提供詳細說明，幫助您實作建議的變更。

您可以忽略不適用於您環境的組態分析。這樣可以避免不必要的警示和不準確的最佳化結果。



[[why-it-matters]]
== 為什麼這很重要

Workload Factory 藉由結合後續評估與建議洞察和修復，將最佳實務做法應用於大型儲存設備、資料庫和 VMware 環境。自動化修復可減少人為錯誤，確保統一管理，並維護工作負載基礎架構的效能和可靠性。

[[best-practices-and-recommendations-for-storage-workloads]]
== 儲存工作負載的最佳實務做法和建議

架構完善的儀表板會根據 ONTAP 最佳實務和 AWS Well-Architected Framework 評估儲存組態。評估也會提出改進和修復建議。

精心設計的分析將組態分類為架構的下列要素：_可靠性_、_安全性_、_卓越營運_、_成本最佳化_和_效能效率_。


NOTE: 目前，Workload Factory 並未針對所有組態提供特定工作負載的建議。請根據特定的工作負載需求自訂您的組態。



[[reliability]]
=== 可靠性

可靠性確保工作負載即使在出現中斷的情況下也能正確、持續地執行其預期功能。

* *檔案物件容量*
+
應提高檔案容量臨界值，以避免達到 Volume 容量限制。檔案容量（inode）過低會導致無法將額外資料寫入 Volume。Workload Factory 建議將檔案容量使用率保持在 80% 以下，以允許建立新檔案。

* *Snapshot 原則*
+
排程本機 Snapshot 快照技術，以實現高效備份和快速還原。Snapshot 快照技術是 Volume 的即時時間點映像。此建議不適用於資料庫環境。

* *SSD 容量餘裕*
+
SSD 儲存層的容量使用率不得超過 80%。否則可能會影響容量資源池儲存層的資料讀寫，進而影響檔案系統的處理量。當容量耗盡時，資料 Volume 將變為唯讀狀態。嘗試寫入新資料的服務也會失敗。





[[operational-excellence]]
=== 卓越營運

卓越營運績效確保工作負載得到有效運作和監控，並能支援使用者的需求。

* *主機可見容量報告*
+
啟用主機可見的容量報告，以提供對 Volume 層級儲存設備使用情況的更佳可見度。

* *Volume 容量餘裕*
+
Volume 容量餘裕應設定為 10%，以因應成長並防止發生意外的容量問題。





[[cost-optimization]]
=== 成本最佳化

成本優化可協助您在保持低成本的同時，為企業創造最大價值。

* *冷資料分層* 使用僅快照分層原則，該原則僅將快照資料移至容量分層，而將作用中資料保留在 SSD 分層。這種方法既能保持資料庫工作負載的低延遲效能，又能降低儲存設備成本。在 7 天冷卻期後將快照資料分層。
* *Snapshot 快照技術清理*
+
刪除不再需要的舊快照或手動建立的快照。刪除它們可以降低成本並減少系統混亂，尤其是在它們並非滿足您的服務等級協定（SLA）或恢復需求的情況下。

* *儲存效率*
+
啟用儲存設備效率提升（資料精簡、壓縮和重複資料刪除），以最佳化儲存使用率並降低 SSD 分層成本。
