= 在 NetApp Workload Factory for Databases 中分析錯誤記錄
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
使用聰明錯誤日誌分析器自動解讀 Microsoft SQL Server 和 Oracle 資料庫錯誤日誌，以便快速識別和解決問題。基於 Agentic AI 的分析需要與 Amazon Bedrock 整合。



[[about-this-task]]
== 關於此任務

錯誤日誌分析和修復有助於維護 SQL Server 執行個體和 Oracle 資料庫的健全狀況和效能。有效解讀錯誤日誌需要細緻的分析和專業知識。手動監控、錯誤偵測和根目錄原因分析既耗時又容易出錯。這些挑戰會導致問題解決延遲、停機增加和營運效率低下。聰明錯誤日誌分析器透過以下主要效益來應對這些挑戰：

* 聰明分組：根據唯一性、嚴重性和類別智慧地合併錯誤，並簡化疑難排解過程，以更快、更有效地解決問題。
* AI 驅動的調查：利用 AI 主動式分析錯誤，提供清晰、可操作的見解，從而加快問題識別速度，而無需深厚的專業知識。
* 錯誤訊息增強：透過外部參考增強錯誤日誌，產品上下文清晰度，從而提高理解和決策能力。
* 最佳實務修復：為在 FSx for ONTAP 上執行的 SQL Server 工作負載提供量身打造的修復建議，讓各種技能等級的使用者都能自信地解決問題。


無論何時使用錯誤日誌分析器，您都可以完全控制自己的環境，同時也能受益於先進的 AI 分析。

若要使用錯誤日誌分析器，您需要啟動 Amazon Bedrock，選擇 Workload Factory 使用的模型，建立連接至 Amazon Bedrock 的私有終端節點，新增權限，並建立企業授權。

link:https://aws.amazon.com/bedrock/pricing/["Amazon Bedrock 定價"^]


NOTE: 如果您的帳戶管理員已關閉 AI 功能，您將看到一則訊息，並且無法使用 AI 分析。請聯絡您的系統管理員或link:../admin/manage-genai-features.html["了解 AI 管理"^]。



[[data-privacy-and-security]]
=== 資料隱私和安全性

此功能透過以下措施確保資料隱私和安全性：

.資料主權
日誌資料和聚合資料保留在您的 AWS 帳戶內，透過私有 VPC 端點（Amazon Bedrock）進行通訊，確保不會暴露於網際網路。

.無 AI 訓練
客戶資料不會用於訓練或改進模型。Amazon Bedrock 會即時處理日誌，但不會使用您的資料進行訓練。結果僅儲存在您的環境中供參考。如需詳細資訊，請參閱 link:https://docs.aws.amazon.com/bedrock/latest/userguide/data-protection.html["Amazon Bedrock 資料保護文件"^]。



[[before-you-begin]]
== 開始之前

若要使用錯誤日誌分析器，您必須符合下列先決條件：

* 您必須在 AWS 帳戶中link:../fsx-storage/add-credentials.html["授予 _查看、規劃和分析_ 權限"^]，才能在 Workload Factory 中建立新的資料庫主機。
* link:../fsx-databases/register-instance.html["註冊資源"^] 在 Workload Factory 中。
* 此外，還必須滿足以下先決條件。在分析日誌錯誤的步驟中，系統會提示您完成這些先決條件。
+
** *Amazon Bedrock 啟動*
+
要讓 Workload Factory 中執行在 SQL Server 或 Oracle 主機的 AI 代理程式能夠無縫地連接到 Bedrock 並取得已識別錯誤日誌的 AI 見解，就需要 Amazon Bedrock。

** *網路*
+
Amazon Bedrock VPC 端點可確保您的 SQL Server 或 Oracle 主機與 Amazon Bedrock API 進行私密通訊，並消除公共網際網路暴露。請確保 Amazon Bedrock VPC 端點與 SQL Server 或 Oracle 主機的子網路關聯（例如：vpce-050cb2f33a1380ffd）。

** *AWS IAM 權限*
+
以下權限是與 SQL Server 或 Oracle 主機關聯的 EC2 執行個體設定檔角色，以及與 Workload Factory 關聯的 AWS 憑證所必需的。

+
*** 具有「bedrock:InvokeModel」權限的 EC2 執行個體設定檔角色
+
此權限允許相應 SQL Server 或 Oracle 主機上的 EC2 執行個體呼叫 Bedrock 模型，以進行主動式錯誤調查和修復指導。此設定檔還可確保安全的 AI 存取，從而獲得客製化的洞察。

*** 與 Workload Factory 關聯的 AWS 憑證：「bedrock:GetFoundationModelAvailability」和「bedrock:ListInferenceProfiles」權限
+
這些權限驗證 SQL Server 或 Oracle 主機所在區域的模型可用度和組態，並確保可靠的、特定於區域的效能。



** *Oracle 使用者權限*
+
下列權限會授予擴充診斷警示的讀取存取權，以便從記錄中擷取錯誤/追蹤詳細資料，以進行 AI 驅動的模式偵測與修復： `V$DIAG_ALERT_EXT`。只有 Oracle 資料庫才需要此權限。

== 分析錯誤日誌

使用 Workload Factory 主控台分析 SQL Server 錯誤記錄。

.步驟
. 登入 link:https://console.netapp.com["NetApp Console"^]。
. 選擇選單 image:workloads-menu-icon.png["漢堡選單圖示用於導覽至 Workloads ，這是 Workload Factory 的選單項目"]，*工作負載* > *資料庫*。
. 從資料庫選單中，選擇 *庫存*。
. 在清單中，選擇 *Microsoft SQL Server* 或 *Oracle* 作為資料庫引擎類型。
. 在「執行個體」標籤中，找到要分析的特定 SQL Server 執行個體或 Oracle 資料庫，然後從選單中選擇 *調查錯誤*。
. 在 *錯誤調查* 標籤中，完成主控台中所述的下列先決條件：
+
** Amazon Bedrock
** 網路：Amazon Bedrock 的私有端點
** EC2 執行個體設定檔角色的權限
** 與工作負載資料庫管理（wlmdb）相關的憑證


. 當滿足先決條件時，請選取 *立即調查* 以使用錯誤日誌分析器，深入了解您的 SQL Server 錯誤日誌。
+
掃描完成後，錯誤會顯示在控制台中，提供智慧錯誤日誌分析器所偵測到問題的全面檢視。

. 使用篩選器，根據嚴重性、時間範圍和錯誤代碼等標準，或根據基礎架構導向的標籤（如運算、儲存設備、網路和安全性）來細化顯示的錯誤。
. 檢閱詳細的錯誤資訊，包括原始錯誤訊息、基於 AI 的解釋，以及建議的補救步驟，以解決錯誤。
