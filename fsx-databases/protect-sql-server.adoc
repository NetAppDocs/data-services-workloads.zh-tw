= 使用 NetApp Workload Factory for Databases 保護 Microsoft SQL Server 工作負載
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
從 Workload Factory 主控台使用 NetApp Backup and Recovery 來保護您的 Microsoft SQL Server 應用程式資料。透過此整合，您可以達成下列保護目標：使用本機主要 Amazon FSx for NetApp ONTAP （FSx for ONTAP） 儲存設備上的本機快照來備份工作負載，並將工作負載複寫到次要 FSx for ONTAP 儲存設備。



[[about-this-task]]
== 關於此任務

Workload Factory 可自動探索資源、驗證先決條件，以及設定與安裝 Microsoft SQL Server 外掛，以準備使用 NetApp Backup and Recovery 來保護您的工作負載。此外掛是 NetApp 軟體的主機端元件，可讓您保護您的 Microsoft SQL Server 工作負載。

NetApp Backup and Recovery 利用 NetApp SnapMirror 資料複寫技術，透過建立快照複本並將其傳輸到備份位置，確保所有備份完全同步。

如需使用 Backup and Recovery 進行保護的詳細資料，請參閱 link:https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-mssql-protect-overview.html["使用備份和復原保護 Microsoft SQL 工作負載總覽"^]。



[[before-you-begin]]
== 開始之前

若要使用備份與復原功能保護 Microsoft SQL Server 工作負載，必須符合下列要求。

* 確保您的環境符合 link:https://docs.netapp.com/us-en/data-services-backup-recovery/concept-start-prereq.html#microsoft-sql-server-workload-requirements["備份與還原 SQL Server 需求"^]。
* link:https://docs.netapp.com/us-en/data-services-backup-recovery/concept-start-prereq.html#in-netapp-console["完成 NetApp Console 需求"^]包括設定、指派 IAM 角色，以及安裝 Console 代理程式。


如果您擁有 NetApp 帳戶的組織系統管理員存取權，當您 <<準備使用 NetApp Backup and Recovery 進行保護,準備使用 NetApp Backup and Recovery 進行保護>> 時，系統會自動指派 `backup and recovery super admin`角色。

* 在 Connector 上設定主機解析
+
若要探索資料庫，您必須在 Connector 上設定主機解析。在託管裝置上，將 IP 位址到主機名稱的對應新增至  `/etc/hosts` 檔案。

+
** link:https://docs.netapp.com/us-en/data-services-backup-recovery/br-start-licensing.html["設定 NetApp Backup and Recovery 的授權"^]






[[prepare-for-protection-with-netapp-backup-and-recovery]]
== 準備使用 NetApp Backup and Recovery 進行保護

使用 NetApp Backup and Recovery 完成保護 Microsoft SQL Server 資源的準備程序。

.步驟
. 登入 link:https://console.netapp.com["NetApp Console"^]。
. 選擇選單 image:workloads-menu-icon.png["漢堡選單圖示用於導覽至 Workloads ，這是 Workload Factory 的選單項目"]，*工作負載* > *資料庫*。
. 從資料庫選單中，選擇 *庫存*。
. 在清單中，選擇 *Microsoft SQL Server* 作為引擎類型。
. 找到要保護的執行個體，然後從選單中選擇 *保護*。
. 如果系統提示，請提供具有管理員存取的 Windows 憑證。
+
若要使用 NetApp Backup and Recovery 進行保護，必須使用 Windows 憑證在 Workload Factory 中註冊 SQL Server 執行個體。

. 如果多個 Console 代理程式處於作用中且可用，請選擇要註冊和保護工作負載的 *Console 代理程式*。
. 為了準備資料保護，Workload Factory 會自動在 Backup and Recovery 中註冊您的 SQL Server 資源，設定並安裝 Microsoft SQL Server 外掛程式，並探索資源以符合保護 SQL Server 執行個體的先決條件。選取 *Start* 以開始程序。
. 滿足先決條件後，選取 *重新導向* 以存取 Backup and Recovery。


.接下來
從 Backup and Recovery 中，建立原則以保護您的 Microsoft SQL Server 執行個體和資料庫。

link:https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-policies-create.html["了解如何建立原則來保護您的 Microsoft SQL Server 執行個體和資料庫"^]。

如需相關資訊，請參閱 link:https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-mssql-protect-overview.html["備份與還原文件"^] 以管理 Microsoft SQL Server 工作負載。



[[edit-protection-for-microsoft-sql-server-resources]]
== 編輯 Microsoft SQL Server 資源的保護

您可以編輯已在 NetApp Backup and Recovery 中受保護的 Microsoft SQL Server 執行個體和資料庫的保護。編輯保護可讓您修改受保護 SQL Server 執行個體的保護原則或排程。

.步驟
. 登入 link:https://console.netapp.com["NetApp Console"^]。
. 選擇選單 image:workloads-menu-icon.png["漢堡選單圖示用於導覽至 Workloads ，這是 Workload Factory 的選單項目"]，*工作負載* > *資料庫*。
. 從資料庫選單中，選擇 *庫存*。
. 在清單中，選擇 *Microsoft SQL Server* 作為引擎類型。
. 選取 *資料庫* 標籤。
. 找到要編輯保護的資料庫，然後從選單中選取 *編輯保護*。
+
您將重新導向至 NetApp Console 中的 Backup and Recovery，您可以在該處修改保護原則或排程。
