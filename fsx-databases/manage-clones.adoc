= 在 NetApp Workload Factory for Databases 中管理資料庫 Clone
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
在 NetApp Workload Factory for Databases 中管理您的沙箱 Clone，以保持您的開發和測試環境可靠且具成本效益的。驗證 Clone 的資料是否完整，將 Clone 連接到您的 CI/CD 傳輸途徑以自動化軟體交付，或重新整理、回復或分割 Clone，使其遵守您目前的開發需求。當您不再需要 Clone 時，請將其刪除以釋放儲存容量。



[[check-sandbox-data-integrity]]
== 檢查沙箱資料完整性

在 NetApp Workload Factory for Databases 中執行完整性檢查，以確定沙箱 Clone 資料是否完整或毀損。

.關於此任務
當您在來源資料庫繁忙時從中建立沙箱 Clone，Clone 的資料可能與來源資料庫的最新快照不同步。此作業會檢查沙箱 Clone 中所有物件的完整性，以判斷沙箱 Clone 資料是否為最新。

.步驟
. 登入 link:https://console.netapp.com["NetApp Console"^]。
. 選擇選單 image:workloads-menu-icon.png["漢堡選單圖示用於導覽至 Workloads ，這是 Workload Factory 的選單項目"]，*工作負載* > *資料庫*。
. 從資料庫選單中，選擇 *沙盒*。
. 在沙盒中，選擇沙盒 Clone 的行動選單來檢查其完整性。
. 選取 *執行完整性檢查*。
. 在「完整性檢查」對話方塊中，按一下 *完整性檢查*。
. 檢查沙箱或作業監控中的完整性檢查狀態。


如果完整性檢查失敗，我們建議您不要使用沙箱 Clone，而是建立一個新的沙箱 Clone。



[[connect-a-sandbox-clone-to-cicd]]
== 將沙箱 Clone 連接到 CI/CD

使用 REST API 程式碼將沙箱 Clone 連接到持續整合和持續交付（CI/CD）傳輸途徑，以透過 NetApp Workload Factory for Databases 中的自動化來改善軟體交付。

.關於此任務
要將新版本的軟體自動交付到資料庫 Clone，您應該連接到 CI/CD 傳輸途徑。使用此操作提供的 REST API 程式碼建立連線。

.步驟
. 登入 link:https://console.netapp.com["NetApp Console"^]。
. 選擇選單 image:workloads-menu-icon.png["漢堡選單圖示用於導覽至 Workloads ，這是 Workload Factory 的選單項目"]，*工作負載* > *資料庫*。
. 從資料庫選單中，選擇 *沙盒*。
. 在沙箱中，選擇沙箱 Clone 的行動選單以連接到 CI/CD 工具。
. 選取 *連線至 CI/CD 工具*。
. 在 CI/CD 對話方塊中，複製或下載連接到 CI/CD 工具所需的 REST API 程式碼。
. 按一下 *Close* 。




[[delete-a-database-clone]]
== 刪除資料庫 Clone

當您不再需要 NetApp Workload Factory for Databases 中的沙盒 Clone，並想要釋放儲存容量時，請將其刪除。

.步驟
. 登入 link:https://console.netapp.com["NetApp Console"^]。
. 選擇選單 image:workloads-menu-icon.png["漢堡選單圖示用於導覽至 Workloads ，這是 Workload Factory 的選單項目"]，*工作負載* > *資料庫*。
. 從資料庫選單中，選擇 *沙盒*。
. 在沙盒中，選擇要刪除的沙盒 Clone 的行動選單。
. 選擇 *Delete*。
. 在「刪除」對話方塊中，選擇 *刪除* 以確認刪除。




[[refresh-a-database-clone]]
== 重新整理資料庫 Clone

在 NetApp Workload Factory for Databases 中重新整理資料庫（沙箱） Clone，使其與目前時刻或先前時間點的來源資料庫相同。

.關於此任務
重新整理 Clone 會將 Clone 更新為來源資料庫的目前狀態，或更新為來源資料庫在先前某個時間點的快照。對沙箱 Clone 所做的任何變更都將被刪除。

.開始之前
只有當來源資料庫處於作用中時，才能重新整理。

若要從快照重新整理資料庫 Clone，來源資料庫必須至少有一個快照才能執行此操作。

.步驟
. 登入 link:https://console.netapp.com["NetApp Console"^]。
. 選擇選單 image:workloads-menu-icon.png["漢堡選單圖示用於導覽至 Workloads ，這是 Workload Factory 的選單項目"]，*工作負載* > *資料庫*。
. 從資料庫選單中，選擇 *沙盒*。
. 在沙盒中，選擇要重新整理的沙盒 Clone 的行動選單。
. 選擇 *Refresh* 。
. 在「重新整理」對話方塊中，選擇下列選項之一：
+
.. *重新整理至目前時間*
.. *重新整理至時間點*
+
對於此選項，請從下拉式選單中選擇要重新整理到的資料庫快照。



. 按一下 *Refresh* 。




[[revert-a-database-clone]]
== 回復資料庫 Clone

在 NetApp Workload Factory for Databases 中，將資料庫（沙盒）Clone 回復到建立時的原始版本。

Clone 資料庫時，建立的 Clone 是 _基線_ Clone。Clone 資料庫中的資料在建立時與來源資料庫完全相同。隨著資料庫 Clone 中的資料隨時間推移而變化，您可能需要將資料回復到最初建立 Clone 時的基線狀態。此操作稱為重新基線化 Clone。重新基線化 Clone 而不是建立新 Clone 可以節省空間；但是，對資料庫 Clone 所做的任何變更都將被刪除。

.步驟
. 登入 link:https://console.netapp.com["NetApp Console"^]。
. 選擇選單 image:workloads-menu-icon.png["漢堡選單圖示用於導覽至 Workloads ，這是 Workload Factory 的選單項目"]，*工作負載* > *資料庫*。
. 從資料庫選單中，選擇 *沙盒*。
. 在沙盒中，選擇要回復的資料庫 Clone 的行動選單。
. 選取 *重新基線*。
. 在「重新基線」對話方塊中，選取 *重新基線*。




[[split-a-database-clone]]
== 分割資料庫 Clone

在 NetApp Workload Factory for Databases 中，從其來源資料庫分割資料庫 Clone 會建立一個新的資料庫，該資料庫將使用一定的儲存容量。分割完成後，Clone 會被刪除，且新的資料庫會出現在清單中。

.開始之前
考慮新資料庫需要多少儲存容量。如有必要，請在開始之前為 FSx for ONTAP 檔案系統link:../fsx-storage/adjust-file-system-capacity.html["增加檔案系統容量"^]。

.步驟
. 登入 link:https://console.netapp.com["NetApp Console"^]。
. 選擇選單 image:workloads-menu-icon.png["漢堡選單圖示用於導覽至 Workloads ，這是 Workload Factory 的選單項目"]，*工作負載* > *資料庫*。
. 從資料庫選單中，選擇 *沙盒*。
. 在沙盒中，選擇要分割的資料庫 Clone 的行動選單。
. 選擇 *分割*。
. 在「分割」對話方塊中，選擇 *分割*。




[[view-a-clones-connection-information]]
== 檢視 Clone 的連線資訊

在 NetApp Workload Factory for Databases 中檢視與複本資料庫 Clone 的連線資訊。

.步驟
. 登入 link:https://console.netapp.com["NetApp Console"^]。
. 選擇選單 image:workloads-menu-icon.png["漢堡選單圖示用於導覽至 Workloads ，這是 Workload Factory 的選單項目"]，*工作負載* > *資料庫*。
. 從資料庫選單中，選擇 *沙盒*。
. 在沙盒中，選擇沙盒 Clone 的行動選單以檢視其連線資訊。
. 選取 *顯示連線資訊*。
. 在「顯示連線資訊」對話方塊中，視需要複製連線資訊。
. 選擇*關閉*。
