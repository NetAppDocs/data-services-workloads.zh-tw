= 在 NetApp Workload Factory 中探索使用 FSx for ONTAP 節省成本
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
探索使用 Amazon Elastic Block Store（EBS）、Elastic File System（EFS）和 FSx for Windows File Server 的儲存設備工作負載與 FSx for NetApp ONTAP 相比可節省的成本。

NetApp Workload Factory 包含儲存設備節省計算器，可將 Amazon 儲存環境與 FSx for ONTAP 進行比較。您可以選擇是否提供 AWS 憑證來探索節省成本的方法，並自訂儲存環境的組態設定。例如，當您提供 AWS 憑證時，您可以選取一個或多個 Amazon Elastic Block Store 執行個體，並讓 Workload Factory 自動進行比較。無論是手動或自動，計算器都會判斷哪種儲存設備服務能以最低成本滿足您的儲存設備需求。

如果儲存設備計算器確定最具成本效益的儲存設備是 FSx for ONTAP，則您可以建立或儲存 FSx for ONTAP 組態，並使用 Codebox 產生基礎架構即程式碼範本，而無需考慮您授予 Workload Factory 的權限。



[[calculator-options]]
== 計算器選項

有兩種計算器選項可用於比較您的系統和 FSx for ONTAP 之間的成本——自訂和自動偵測您的 Amazon 儲存環境。

透過自訂探索節省成本：您可以提供儲存環境的組態設定，包括使用案例、區域、Volume 或檔案系統的數量、儲存設備量、快照頻率、每次快照變更的量、預置 IOPS、處理量等等。

探索已偵測到的儲存環境的節省方案：Workload Factory 會連接到您現有的 AWS 儲存環境，並將詳細資訊匯入計算器進行自動比較。您需要授予自動化權限才能使用自動模式。您可以更改使用案例，但所有其他詳細資訊都會在計算中自動確定。

此外，您還可以 link:add-credentials.html["新增 AWS 憑證"^] 來提高計算機分析的準確性。選擇 *基於現有資源計算節省額*。您將被重新導向至「新增憑證」頁面。新增憑證後，選擇要與 FSx for ONTAP 進行比較的現有資源，然後選擇 *檢視節省額*。



[[explore-savings-via-customization]]
== 透過自訂探索節省成本

請按照您選擇的儲存設備選項標籤下的步驟操作。

[role="tabbed-block"]
====
.Amazon Elastic Block Store （EBS）
--
.步驟
. 登入 link:https://console.netapp.com["NetApp Console"^]。
. 選擇選單 image:workloads-menu-icon.png["漢堡選單圖示用於導覽至 Workloads ，這是 Workload Factory 的選單項目"]，*工作負載* > *儲存設備* > *FSx for ONTAP*。
. 從 *FSx for ONTAP* 中選擇 *探索節省*，然後選擇 *Amazon Elastic Block Store (EBS)* 標籤。
. 在儲存設備節省計算器中，請提供下列詳細資訊：
+
.. *使用案例*：必填。請從下拉式選單中選擇使用案例。所選使用案例將決定用於比較的 FSx for ONTAP 檔案系統特性。
.. *區域*：可選。請從下拉式選單中選擇 EBS 組態所在的區域。
.. *選擇 EBS Volume 類型*：選用。選擇組態中使用的 EBS Volume 類型。
.. *Volume 數量*：選用。請輸入您的 EBS 組態中的 Volume 數量。
.. *每 Volume 儲存容量（TiB）*：選用。請輸入每 Volume 儲存容量，單位為 TiB。
.. *Snapshot 快照技術頻率*：選用。請為您的 EBS 組態選擇 Snapshot 快照技術頻率。
.. *每個快照變更量（GiB）*：選填。僅適用於快照儲存設備。請輸入每個快照的變更量（以 GiB 為單位）。
.. *每個 Volume 的預置 IOPS*：選用。適用於 gp3、io1 和 io2 Volume。輸入每個 Volume 的預置 IOPS。
.. *處理量（MiB/s）*：選用。僅適用於 gp3 Volume。請輸入每個 Volume 的處理量（單位：MiB/s）。




--
.Amazon FSx for Windows File Server
--
.步驟
. 登入 link:https://console.netapp.com["NetApp Console"^]。
. 選擇選單 image:workloads-menu-icon.png["漢堡選單圖示用於導覽至 Workloads ，這是 Workload Factory 的選單項目"]，*工作負載* > *儲存設備* > *FSx for ONTAP*。
. 從 *FSx for ONTAP* 中選擇 *探索節省*，然後選擇 *Amazon Elastic Block Store (EBS)* 標籤。
. 在儲存設備節省計算器中，請提供下列詳細資訊：
+
.. *使用案例*：必填。請從下拉式選單中選擇使用案例。所選使用案例將決定用於比較的 FSx for ONTAP 檔案系統特性。
.. *區域*：選用。請從下拉式選單中選擇 FSx for Windows File Server 組態的區域。
.. *部署類型*：選用。選擇 *單一可用度區域* 或 *多個可用度區域*。
.. *儲存類型*：預設選擇 SSD 儲存設備類型。
.. *儲存容量（TiB）*：選用。請輸入組態的儲存容量。
.. *重複資料刪除節約效益（%）*：選用。請輸入您預期透過重複資料刪除獲得的容量節約效益百分比。
.. *Snapshot 快照技術頻率*：選用。為您的組態選擇 Snapshot 快照技術頻率。
.. *每個快照變更量（GiB）*：選填。僅適用於快照儲存設備。請輸入每個快照的變更量（以 GiB 為單位）。
.. *已配置的 SSD IOPS*：選用。輸入已配置的 SSD IOPS。
.. *處理量（MiB/s）*：可選。請輸入處理量，單位為 MiB/s。




--
.Amazon Elastic File System（EFS）
--
.步驟
. 登入 link:https://console.netapp.com["NetApp Console"^]。
. 選擇選單 image:workloads-menu-icon.png["漢堡選單圖示用於導覽至 Workloads ，這是 Workload Factory 的選單項目"]，*工作負載* > *儲存設備* > *FSx for ONTAP*。
. 從 *FSx for ONTAP* 中選擇 *探索節省*，然後選擇 *Amazon Elastic Block Store (EBS)* 標籤。

.. *區域*：選用。請從下拉式選單中選擇 FSx for Windows File Server 組態的區域。
.. *檔案系統類型*：選用。選擇 *區域* 或 *單一區域*。
.. *儲存容量（TiB）*：選用。輸入 EFS 組態的儲存容量。
.. *經常存取的資料（%）*：選用。輸入經常存取資料的百分比。
.. *處理量模式*：選用。選擇*預置處理量*或*彈性處理量*。
.. *處理量（MiB/s）*：可選。請輸入處理量，單位為 MiB/s。

[[explore-savings-for-detected-storage-environments]]
== 探索已偵測到的儲存設備環境的節約效益

.開始之前
若要讓 Workload Factory 能夠偵測到您 AWS 帳戶中的 Amazon Elastic Block Store （EBS）、Elastic File System （EFS） 和 FSx for Windows File Server 儲存設備環境，請確保您在 AWS 帳戶中link:add-credentials.html["授予 _查看、規劃和分析_ 權限"^]。


NOTE: 此計算器選項不支援 EBS 快照和 FSx for Windows File Server 陰影複製的計算。在探索透過自訂節省成本時，您可以提供 EBS 和 FSx for Windows File Server 快照的詳細資訊。

請按照您選擇的儲存設備選項標籤下的步驟操作。

[role="tabbed-block"]
====
.Amazon Elastic Block Store （EBS）
--
.步驟
. 登入 link:https://console.netapp.com["NetApp Console"^]。
. 選擇選單 image:workloads-menu-icon.png["漢堡選單圖示用於導覽至 Workloads ，這是 Workload Factory 的選單項目"]，*工作負載* > *儲存設備* > *FSx for ONTAP*。
. 從 *FSx for ONTAP* 中選擇 *探索節省*，然後選擇 *Amazon Elastic Block Store (EBS)* 標籤。
. 在 *Elastic Block Store（EBS）* 索引標籤中，選取要與 FSx for ONTAP 比較的執行個體，然後選取 *Explore savings*。
. 儲存節省計算器隨即顯示。以下儲存系統特性已根據您選擇的執行個體預先填寫：
+
.. *使用案例*：您的組態的使用案例。如有需要，您可以變更使用案例。
.. *選定的 Volume*：EBS 組態中的 Volume 數量
.. *總儲存設備量（TiB）*：每個 Volume 的儲存設備量（單位：TiB）
.. *總配置 IOPS*：適用於 gp3、io1 和 io2 Volume
.. *總處理量（MiB/s）*：僅適用於 gp3 Volume




--
.Amazon FSx for Windows File Server
--
.步驟
. 登入 link:https://console.netapp.com["NetApp Console"^]。
. 選擇選單 image:workloads-menu-icon.png["漢堡選單圖示用於導覽至 Workloads ，這是 Workload Factory 的選單項目"]，*工作負載* > *儲存設備* > *FSx for ONTAP*。
. 從 *FSx for ONTAP* 中選擇 *探索節省*，然後選擇 *Amazon FSx for Windows File Server* 索引標籤。
. 在 *Amazon FSx for Windows File Server* 標籤中，選擇要與 FSx for ONTAP 進行比較的執行個體，然後選擇 *探索節省*。
. 此時將顯示儲存節省計算器。以下儲存系統特性已根據您選擇的執行個體部署類型預先填入：
+
.. *使用案例*：您的組態的使用案例。如有需要，您可以變更使用案例。
.. *選定的檔案系統*
.. *總儲存設備容量（TiB）*
.. *已配置 SSD IOPS*
.. *處理量（MiB/s）*




--

--
.步驟
. 登入 link:https://console.netapp.com["NetApp Console"^]。
. 選擇選單 image:workloads-menu-icon.png["漢堡選單圖示用於導覽至 Workloads ，這是 Workload Factory 的選單項目"]，*工作負載* > *儲存設備* > *FSx for ONTAP*。

.. *使用案例*：您的組態的使用案例。如有需要，您可以變更使用案例。

[[deploy-fsx-for-ontap-file-systems]]
== 部署 FSx for ONTAP 檔案系統

如果您想要切換至 FSx for ONTAP 以實現成本節約效益，請選擇 *建立* 以直接從「建立 FSx for ONTAP 檔案系統精靈」建立檔案系統，或選擇 *儲存* 以儲存建議的組態以供日後使用。

部署方法:: 擁有 _檔案系統建立_ 權限，您可以直接從 Workload Factory 部署 FSx for ONTAP 檔案系統。您也可以從 Codebox 視窗複製內容，並使用其中一種 Codebox 方法來部署系統。
+
--
擁有 _檢視、規劃和分析_ 權限後，您可以從 Codebox 視窗複製內容，並使用其中一種 Codebox 方法來部署 FSx for ONTAP 檔案系統。
